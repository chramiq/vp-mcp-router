# 0011: Zoom loop (neighborhood, server-side crop)

## Context

Full reads suffocate on large diagrams, and VP's `Rectangle` export
overloads demonstrably do not crop (eye-verified on both overloads;
see ADR-0010). The agent workflow needs list → traverse → focus →
screenshot → ingest.

## Decision

- `vp_get_neighborhood {vpp_url, element, depth}`: N-hop BFS over the
  extractor graph in `vpmcp.graph.Neighborhood` (VP-free, unit-tested).
  Unknown center is an explicit error, not an empty success.
- Crop in our server, not VP's: full PNG render, then `getSubimage`.
  Coordinate mapping measured from the SVG export (element rects keep
  VP sizes 1:1; origin is content-min plus a 2px margin): pixel box =
  shift by `-contentMin + 2`, clamped. `crop` takes explicit boxes,
  `crop_to_element` frames a view id with 20px padding. PNG only;
  SVG zooms via viewBox client-side.
- Verified live: neighborhood of Classt returns exactly its two
  linked classes; `crop_to_element` on Class3 returns a 120x80 frame
  containing only Class3, ingested directly.

## Consequences

- RENDER_MARGIN (2px) is measured on 18.1; clamp absorbs drift, and a
  wrong future margin degrades framing, never errors.
- Skill documents the zoom sequence as the default large-diagram flow.
