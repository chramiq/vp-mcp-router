# 0012: Explicit save tool, safe restarts

## Context

An autonomous SIGTERM restart cycle lost 5 fresh edges: kills only
*sometimes* persist tail state, and "probably saved" is not a
standard. The plugin cannot restart VP itself (no such API), but it
can save (`ProjectManager.saveProject()` + `IProject.getProjectFile()`).

## Decision

- New `vp_save_project {confirm:true}` reporting `{saved, project,
  file}`. Confirm-gated like apply.
- Restart discipline (AGENTS.md): before killing, save via the tool
  and verify the `.vpp` mtime moved past the last mutation; if not,
  do not kill — ask the user to save.
- Skill: offer save after clean batches, never auto-save.
- Member pinning (`from_member`/`to_member` on connect) shipped in
  the same cycle: VP honors API-set member ids, though UI drag-drop
  never populated them. Validator accepts non-blank ids; apply pins
  post-connector.

## Consequences

- Restarts are safe by construction instead of by luck.
- The lost edges remain the standing argument for saving early.
- Never-saved projects are refused upfront: with no `.vpp` file,
  `saveProject()` blocks on a native Save-As dialog instead of failing,
  so the tool checks `getProjectFile()` first and tells the user to
  save once in VP.
